## 四、本项目 A1 的特殊说明

### 1. 零依赖，无法复现「缺依赖崩溃」

课程标准第 1 周的微实验是「在缺依赖的环境跑同伴代码，看崩溃」。

**本作品是纯前端零依赖**：双击 `index.html` 即可运行，不装任何东西。
所以传统做法无法复现。

**改编方案**：依赖从「软件包」换成「文件结构 + 浏览器」，做了三组缺文件实验，
并发现最危险的一种失败是**静默失败**（缺 `脚本.js` 时页面外观正常但完全无响应）。

详见 `A1-运行证据.md`。

### 2. 四个实验覆盖了四类不同问题

| | 实验一 | 实验二 | 实验三 | 实验四 |
|---|---|---|---|---|
| 类型 | 参数实验 | 布局缺陷 | 算法缺陷（多样性） | 算法缺陷（约束） |
| 发现方式 | 主动设计 | 自测清单 | 用户使用 | 用户使用 |
| 现有 81 项测试能否发现 | 能 | **不能** | **不能** | **不能** |
| 课程对应 | 参数与影响分析 | 第8周 画蛇添足 | 第10周 缺陷复现 | 第1周 焦油坑 |

**这四类问题加起来的说服力，比单一类型的实验更强**——
既证明了「会主动做参数实验」，也证明了「能接住真实使用中发现的问题」。

### 3. 一个诚实记录

实验三修复后，**引入了实验四的超额缺陷**。

这没有隐藏，而是完整记录了下来，并在实验四里分析了根因：
把「不超额度」这个硬约束，错误地与「每道菜都出现」这个软目标做了交换。

**「第一次修好不等于真的好了」**，这也是这份作业想说明的核心。
