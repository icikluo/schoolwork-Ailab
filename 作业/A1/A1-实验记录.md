# A1 实验记录：减脂人群系数 0.8 → 0.7

## 一、实验目的

对应 A1 第 3 评分项「个人改动与解释」：手工修改作品中的一处核心参数，
观察影响范围，并能用自然语言解释执行流的变化。

**改动位置**：`脚本.js` 第 16 行 `人群系数` 中的 `减脂`

```diff
  var 人群系数 = {
-   减脂: 0.8,
+   减脂: 0.7,
    增肌: 1.1,
    控糖: 1.0,
    均衡: 1.0
  };
```

| 阶段 | 基础代谢 | 每日消耗 | 调整后 | 取整到 10 | 推荐第一道 |

## 五、执行流解释

1. 点击「计算目标」触发 `设置目标()`，读取六个表单值。
2. `计算目标卡路里()` 依次执行三步：
   - **第一步**：`计算基础代谢()` 用 Mifflin-St Jeor 公式，得 1255.3
   - **第二步**：乘活动系数 1.375，得 1726
   - **第三步**：乘人群系数（0.8 或 0.7），得 1380.8 或 1208.2
3. 最后 `Math.round(值 / 10) * 10` 取整到 10，分别得到 1380 和 1210。
4. 若取整后小于 1200，则强制上调为 1200。

## 六、影响链路

改一个系数，下游三处跟着变：

1. **目标大数字**：1380 → 1210
2. **进度栏**「/ 目标」：1380 → 1210
3. **推荐结果**：每餐预算 = 剩余 ÷ 3，从 460 降至约 403，
   最接近预算的菜由 420 的鲈鱼饭变成 400 的鸡胸肉卷饼

## 七、实验中发现并修复的真实缺陷

### 现象

把系数改回 0.8 并刷新页面后：

- 顶部「每日目标卡路里」显示 **1380**（按新代码重算）
- 下方「今日摄入 / 目标」显示 **1210**（读浏览器存档的旧值）

同一页面两个数字互相矛盾（见 `A1-03`）。

### 原因

`初始化()` 只用当前代码重新计算并**显示**结果，没有把新值**写回** localStorage。
于是顶部走「实时计算」，进度栏走「读存档」，两个数据源各说各话。

### 修复

```javascript
var 结果 = 计算目标卡路里(...);
if (结果.目标 !== 目标.目标) {
  目标.目标 = 结果.目标;
  写目标(目标);        // 关键：回写，统一数据源
}
显示目标结果(结果);
```

### 对应课程知识点

这正是课程标准 U3「概念完整性 / 接口契约断裂」所描述的问题：
两个模块各自独立运行都正常，一旦对同一份数据的理解不一致，联动时就出现矛盾。
本次是在自己的作品中真实复现并修复，而非课本案例。

## 八、还发现的一个边界

当前配置下目标值 1210，距离 1200 安全下限**只有 10 kcal**。
若系数再降到约 0.69，结果会低于 1200 并触发下限保护，被强制拉回 1200。
这说明下限判断必须放在取整之后执行。
