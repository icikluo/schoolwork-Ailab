# A1 实验记录（二）：食谱专区「记录」按钮被裁出卡片

> 对应 A1 第 3 评分项：**个人改动与解释（2 分）**
> 发现日期：2026-11-14 ｜ 提交：见本文末尾

---

## 一、发现过程

在按 A1 验收契约第 6 项自测时，要求「在食谱专区点一道菜的『记录』按钮」。

**实际操作时发现：食谱专区里根本找不到「记录」按钮。**

卡片底部只有两个控件：「做法」和「整份」。

第一反应是"功能没做"，于是去 `脚本.js` 里查，发现**按钮是有的**：

```javascript
// 脚本.js 第 434–441 行
var 按钮 = document.createElement("button");
按钮.className = "加入按钮";
按钮.textContent = "记录";
按钮.addEventListener("click", function () {
  添加记录(菜, null, Number(份量选择.value));
});
按钮组.appendChild(按钮);
```

**按钮确实被创建并追加到 DOM 里，也绑定了点击事件。**

那为什么看不见？

---

## 二、定位：用测量代替猜测

在页面里注入一段测量脚本，读取按钮的实际位置：

```javascript
var r = 记录按钮.getBoundingClientRect();
isClipped = r.right > 卡片.getBoundingClientRect().right;
```

### 修复前的测量结果

```
卡片宽:        215px
按钮数:        2（可见）
  「做法」 宽 52  右边界 514  被裁: false
  「记录」 宽 64  右边界 638  被裁: true   ← 超出卡片右边界 580
```

**结论：「记录」按钮存在、能被点击，但超出了卡片右边界约 58px，被 `overflow:hidden` 裁掉，用户完全看不见。**

---

## 三、根因

`样式.css` 中按钮组的定义：

```css
.卡按钮组 { display: flex; align-items: center; gap: 6px; }
```

**缺少 `flex-wrap: wrap`**，三个子元素被强制排在一行：

| 控件 | 宽度 |
|---|---|
| 做法按钮 | 52px |
| 份量选择（整份/半份） | ≈ 62px |
| 记录按钮 | 64px |
| 3 个 gap | 12px |
| **合计** | **≈ 190px** |

卡片内容区宽度约 213px，再扣掉左侧的热量数字（"320 kcal"），**放不下，于是最后的「记录」被挤出边界**。

### 为什么会变成这样

这是后期迭代引入的回归：

- 最初只有「记录」一个按钮 → 放得下
- 后来加了「整份/半份」份量选择 → 开始紧张
- 再加「做法」展开按钮 → 彻底放不下

**每加一个功能时单独看都没问题，合在一起就崩了。** 正是课程标准第 8 周《画蛇添足》描述的场景。

---

## 四、修复

```css
/* 修改前 */
.卡按钮组 { display: flex; align-items: center; gap: 6px; }

/* 修改后 */
.卡按钮组 {
  display: flex;
  align-items: center;
  gap: 6px;
  flex-wrap: wrap;          /* 排不下时换行，不让子元素溢出 */
  justify-content: flex-end;
}
.做法按钮 { padding: 6px 10px; flex: none; }   /* 略微收窄内边距 */
.份量选择 { flex: none; }                      /* 不允许被压缩 */
.食谱卡 .加入按钮 { flex: none; white-space: nowrap; }
```

**为什么选换行而不是删功能**：

- 「做法」和「整份」都是有用功能，不该为了腾地方删掉
- 换行后窄屏自动排成两行，宽屏仍是一行，自适应
- 只改 CSS，不动 JS，风险最低

## 六、这个 bug 说明了什么

### 1. 代码正确 ≠ 用户可用

| 视角 | 结论 |
|---|---|
| 代码 | 按钮创建了、事件绑定了、函数正确 |
| 自动化测试 | 81 项全过（测的都是函数，不是布局） |
| **用户** | **根本看不到按钮，认为功能不存在** |

如果没有真人按验收清单点一遍，这个 bug 会一路带到期末。

### 2. 测试的盲区

现有 81 项测试都是**逻辑测试**（验证函数输入输出），没有一项检查**布局**。
这类问题只有两种发现方式：

- 真人点一遍（本次就是这样发现的）
- 自动化 UI 测试（如 Playwright 检查元素是否在视口内）

本次是前者。

### 3. 与课程知识点的对应

| 课程内容 | 本次体现 |
|---|---|
| 第 1 周《焦油坑》 | 「能跑」与「能用」之间隔着交付鸿沟 |
| 第 5 周《概念完整性》 | HTML 结构与 CSS 布局之间的契约被打破 |
| 第 8 周《画蛇添足》 | 每加一个功能都把原有控件往外挤，最后挤没了 |
