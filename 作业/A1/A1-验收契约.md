## 一、一句话验收契约

> **用户打开网页 → 填写身体数据点「计算目标」→ 页面显示一个每日目标卡路里 →
> 从食谱列表点「记录」→ 上方卡路里数字增加、进度条变长 →
> 当已摄入超过目标时，进度条变红 →
> 「为你推荐」列出 3 道属于当前人群、且今天还没吃过的菜。
> 顶部可切换到「💪 训练」分区，按部位浏览 28 个健身动作教程。**

以上每一步都是**肉眼可观察的**，不需要任何人额外解释，也不需要看代码。

## 二、输入契约

| 输入项 | 类型 | 取值范围 | 默认值 | 必填 |
|---|---|---|---|---|
| 性别 | 单选 | 男 / 女 | 女 | 是 |
| 年龄 | 整数 | 10 – 100 | 22 | 是 |
| 身高 | 小数 | 100 – 250 cm | 165 | 是 |
| 体重 | 小数 | 25 – 200 kg | 55 | 是 |
| 活动量 | 单选 | 1.2 / 1.375 / 1.55 / 1.725 | 1.2（久坐） | 是 |
| 人群 | 单选 | 减脂 / 增肌 / 控糖 / 均衡 | 减脂 | 是 |

**输入边界处理**：

- 空值或非数字 → 浏览器原生校验拦截，无法提交
- 超出范围 → 输入框的 `min` / `max` 属性拦截
- 所有输入均不涉及个人隐私信息的存储或上传

## 三、输出契约

### 3.1 每日目标卡路里

| 输出项 | 格式 | 举例 |
|---|---|---|
| 目标卡路里 | **10 的整数倍** | `1380` |
| 计算过程链 | 文本，三段 | `基础代谢 1255.3 kcal → 每日消耗 1726 kcal → 调整后 1380.8 kcal` |

**两条硬性规则**：

1. 结果必须能被 10 整除。
2. 结果不得低于 1200；若低于，强制显示 1200 并追加提示「已自动上调」。

### 3.2 营养汇总

| 指标 | 单位 | 精度 |
|---|---|---|
| 卡路里 | kcal | 整数 |
| 碳水 | g | 1 位小数 |
| 脂肪 | g | 1 位小数 |
| 膳食纤维 | g | 1 位小数 |
| 蛋白质 | g | 1 位小数 |

### 3.3 推荐结果

- 数量：**3 道**（可选食谱不足 3 道时显示实际数量）
- 必须全部带有**当前人群**的标签
- 必须是**今天尚未记录**的菜
- 剩余额度 ≤ 100 kcal 时，不再推荐，显示「今日已达目标额度」

### 3.4 宏量营养目标

| 输出项 | 显示位置 | 举例 |
|---|---|---|
| 碳水 / 脂肪 / 蛋白质目标（g） | 首屏「今日摄入」各营养项旁 | `g / 目标 173` |

- 设置目标后按人群供能比换算；未设置目标时只显示单位 `g`。

### 3.5 训练分区

- 顶部导航两个分区：🥗 饮食 / 💪 训练，可来回切换
- 动作按 上肢 / 下肢 / 核心 / 全身 四个分区浏览，共 28 个（每部位 7 个，卡片带器械标签）
- 每个动作卡片含：目标肌群、要点（3–5 条）、常见错误（1–3 条）、建议组数、配图
- 有照片的显示本地照片，无照片的自动显示 SVG 示意图，**不出现裂图**
- 分区底部有「安全说明」卡片，明确声明不构成专业教练指导或医疗建议

## 五、「完成」的定义（Definition of Done）

对照课程标准「运行不等于完成，交付必须有证据」，本作品的完成标准是：

| 维度 | 满足条件 |
|---|---|
| 能运行 | 双击即可打开，无需安装任何依赖 |
| 可观察 | 上述 35 项检查全部通过（第 33 项可由测试脚本代替） |
| 可交接 | 他人仅凭 `README.md` 就能复现与操作 |
| 有证据 | 30+ 条规范提交记录 + 5 个自动化测试脚本全绿（其中逻辑复算 81 项） |

## 六、明确不验收的内容（对应三不原则）

以下**不属于**本次交付的验收范围，缺了不算失败：

1. 账号注册、云端同步、多用户
2. 在线营养数据库 / AI 生成食谱库数据 / 实时联网搜索
3. 一个月（30 天）食谱计划
4. 可视化图表（环形图、趋势曲线等，含训练数据的图表）
5. 摄像头动作识别与实时姿态纠正
6. AI 助手（v0.3 曾接入，v0.4 已移除，不再属于交付范围）

## 七、已知限制

1. 营养数据为教学用估算值，**不构成医学或营养建议**。
2. 历史记录只保留最近 7 天的纯文字回看（v0.4.1），不做更长历史与图表。
3. 推荐不考虑口味偏好、过敏原、烹饪时间。
4. 训练动作为通用参考，不针对个人体态定制。
5. 餐次按记录时刻自动归类（早 / 午 / 晚 / 加餐），不支持手动改餐次。
6. 需在现代浏览器打开（Chrome / Edge），不支持 IE。
