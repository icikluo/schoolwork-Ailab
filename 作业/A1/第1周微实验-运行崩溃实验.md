## 四、真正的问题

查测试脚本的根路径定义：

| 文件 | 修复前的根路径 |
|---|---|
| `核对数据.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `核对动作.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `逻辑复算.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `检查契约.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `核对商店.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `校验schema.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `基准商店.py` | `Path(r"D:\lab\自选作品")` ❌ |
| `核对养成.py` | `Path(__file__).resolve().parent.parent` ✅ |

**8 个测试里 7 个写死了原始绝对路径。**

所以当我在副本目录执行 `python 测试/核对动作.py` 时，它读的是
`D:\lab\自选作品\数据\动作.js`——**原目录的那份**，不是副本。

> **测试全绿，但它检查的根本不是我搬过去的那份代码。**

## 五、这比"运行崩溃"严重在哪

课程设计的是"报错崩溃"，我的项目跑出来的是"静默通过"：

| | 常规微实验 | 本项目的情况 |
|---|---|---|
| 现象 | 报错、崩溃、缺模块 | **全绿通过** |
| 学生能否察觉 | 能，一眼看到红 | **不能，看起来一切正常** |
| 真实状态 | 环境依赖没声明 | **校验了错误的目录** |
| 危险等级 | 低（暴露问题） | **高（掩盖问题）** |

**报错是好事，假绿才是灾难。** 一个会喊疼的系统还能修；
一个不喊疼但已经坏了的系统，会在你以为没问题的某天突然出问题。

## 六、修复

7 个脚本统一改为与 `核对养成.py` 相同的写法：

```python
根 = Path(__file__).resolve().parent.parent
```

含义：从**当前脚本所在位置**往上倒两层（`测试/` → `自选作品/`）。
无论项目被复制到哪个盘、哪个目录，它都会找对自己身边的那份数据。

提交：`a647ac9`

---

## 七、修复后的验证（关键）

光"改完还全绿"不能证明修复有效——因为改之前也是全绿。必须做**鉴别实验**：

| 实验 | 期望 | 实际 |
|---|---|---|
| A. 原目录跑九项 | 全绿（行为不能变） | ✅ 9/9 |
| B. 干净副本、数据未破坏 | 全绿 | ✅ 8/8 |
| **C. 干净副本里故意改坏数据**（把 e030 名称改成与 e009 重复） | **必须报错** | ✅ 报「名称 存在重复值」，exit=1 |
| **D. 同一时刻原目录** | **必须仍然全绿**（证明没串目录） | ✅ exit=0 |

**C 和 D 同时成立，才证明测试现在检查的是自己所在的目录。**
如果在修复前做这个实验，C 会是绿的——因为它去查原目录了。

## 八、这个实验教了我什么

### 1. "能跑"和"能交接"是两件事

第一天就能打开的网页，不等于第二天换台电脑还能被正确验证。

### 2. 全绿不等于正确

这是本项目第二次踩到同一个教训：
- 第一次在 A4 交接实测：代理加出重复动作，九项全绿
- 这一次：测试校验了错误的目录，九项全绿

**两次都是"测试通过但结果错误"。** 测试能证明的，永远只是"我检查的那些点没问题"，
它证明不了"我检查的是对的东西"。

### 3. 验证修复要用"鉴别实验"

改完还全绿，说明不了任何问题——因为改之前也全绿。
必须构造一个**改之前会绿、改之后会红**的场景，才叫证明了修复有效。
这和 A2 学到的"指纹能证明恢复、测试不能"是同一个方法论。

### 4. 绝对路径是工程交付的隐形债

写 `D:\lab\自选作品` 的那天很省事，代价是这行代码在别人的电脑上毫无意义。
`__file__` 相对推导多打几个字，换来的是"复制到哪都能用"。
