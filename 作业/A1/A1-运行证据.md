---

## 一、课程微实验原设计

课程标准第 1 周微实验：

> **运行崩溃实验**：在缺少全局依赖的干净虚拟机或新终端窗口中直接执行同伴拷贝的未封装脚本，
> 观察模块缺失或路径报错现象，体悟「在我的机器上能跑」不等于工程交付。

该实验的前提是**作品本身带有外部依赖**（如 Python 的第三方库）。

## 二、本作品的特殊情况

**食谱搭配是零依赖作品**：纯 HTML + CSS + JavaScript，双击 `index.html` 即可运行，
不安装 Node.js、不装任何第三方包、不连网络、不需要构建。

因此**无法复现「缺依赖崩溃」**——这本身是设计选择，不是缺陷。但它带来一个必须回答的问题：

> 既然不需要依赖，那这个作品是否也存在「只能在我电脑上跑」的风险？

**答案是：存在。** 只是风险来源不同。

## 三、替代实验设计

依赖换成了**文件与浏览器环境**。作品运行时依赖三样东西，缺一样就跑不起来：

| 依赖 | 作用 | 缺失后果 |
|---|---|---|
| `样式.css` | 全部视觉样式 | 页面变无样式白底黑字，布局塌陷 |
| `数据/食谱.js` | 提供 `window.食谱数据` | 脚本取不到数据，抛 TypeError，列表全空 |
| `脚本.js` | 全部交互逻辑 | 页面只剩静态外壳，点按钮无反应 |

于是把课程原微实验改编为：**在文件不完整的环境中运行作品，观察它如何失败。**

## 四、实验步骤（可直接照做）

### 准备

1. 复制整个 `自选作品` 文件夹到新位置，命名 `实验-缺文件`。
2. 用浏览器打开 `index.html`，**确认完整版能正常显示**（对照组）。
3. 关闭页面。

### 实验 A：缺少样式

1. 把 `样式.css` 改名为 `样式.css.bak`。
2. 打开 `index.html`。

**预期观察**：页面能打开，但**完全没有蓝色、没有卡片边框、没有排版**，
内容挤成一列黑字。功能可能仍可用，但**看起来根本不像一个作品**。

> 体悟：视觉资源也是交付的一部分。缺了它，功能完好但用户不敢用。

### 实验 B：缺少数据

1. 恢复 `样式.css`，把 `数据/食谱.js` 改名为 `食谱.js.bak`。
2. 打开 `index.html`，按 F12 打开开发者工具，切到 Console 面板。

**预期观察**：

- 「全部食谱」「为你推荐」「今日已记录」三个区域**全部空白**
- Console 中报错：`TypeError: Cannot read properties of undefined`

> 体悟：数据与逻辑拆开存放，一旦路径断裂，整个功能链断掉。

### 实验 C：缺少逻辑

1. 恢复 `数据/食谱.js`，把 `脚本.js` 改名为 `脚本.js.bak`。
2. 打开 `index.html`。

**预期观察**：

- 页面**外观完全正常**，白蓝配色、卡片布局都在
- 但**所有内容都是空的**，点「计算目标」**没有任何反应**
- 不报错，不崩溃，只是「什么都没发生」

> 体悟：**这是最危险的一种失败**。页面看起来好好的，用户以为是自己操作错了，
> 而不是程序坏了。比直接报错更难排查。

## 六、另一种验证方式：干净环境复现

除了「刻意删文件」，还做了一次**真实的新环境复现**：

1. 从 git 仓库重新克隆到全新目录
2. 在克隆副本中直接打开 `index.html`
3. 运行全部自动化测试

**结果**：9 个文件完整到位，25 项检查全部通过，**无需任何额外说明或安装步骤**。

```bash
git clone <仓库地址> 新目录
cd 新目录/自选作品
python 测试/核对数据.py     # 24 条食谱符合字段契约
python 测试/逻辑复算.py     # 25 项全部通过
```

这条证据证明的是**「别人拿到仓库就能跑」**，
比单机截图更有说服力，对应课程标准里「可交接」的要求。

## 七、结论

### 发现了什么

1. 零依赖不等于零风险。作品的「依赖」从**软件包**变成了**文件结构 + 浏览器**。
2. **最危险的不是报错，是静默失败**（实验 C）——页面看起来正常却完全不可用。
3. 三种失败的排查难度不同：报错的（B）最好查，无报错的（C）最难查。

### 对作品的改进

基于实验 C 的发现，可以在 `脚本.js` 开头加一道自检：

```javascript
if (typeof window.食谱数据 === "undefined") {
  document.body.innerHTML =
    '<p style="padding:40px;text-align:center">数据文件未加载，请确认 数据/食谱.js 存在。</p>';
}
```

这样当数据缺失时，用户看到的是**明确的提示**，而不是一片空白。
（此项列入后续改进，不在本版本范围内）

### 与课程标准的对应

| 课程标准要求 | 本实验如何体现 |
|---|---|
| 「在我的机器上能跑」≠ 工程交付 | 同样是缺一样东西就跑不起来，只是缺的不是 pip 包 |
| 建立环境依赖与最小验收条件 | 明确了三样必需文件，并写进 README |
| 体悟交付的脆弱性 | 实验 C 证明了「看起来对」和「真的对」是两回事 |
