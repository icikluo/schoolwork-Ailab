# PRD · 食谱搭配网页

版本：v0.6.0 ｜ 更新日期：2026-11-17 ｜ 状态：7 个独立页面 + 左侧常驻导航 + 一页一功能区；新增「我的小窝」养成页（3D 客厅 + 手机桌面 + 像素宠物），饮食与训练功能不变，仍为纯离线

---

## 一、一句话描述

一个网页：用户填身体数据得到每日目标卡路里，按人群选择并打卡食谱，系统根据剩余额度自动推荐下一餐；
另设训练分区，按部位提供健身动作教程（姿势与要点）。

## 二、用户是谁

- 主要用户：想简单管理每日饮食与基础训练的大学生（本课程同学）。
- 使用场景：
  - 饮食：中午吃完饭后打开网页记录一下，看今天还剩多少额度、晚上该吃什么。
  - 训练：练之前查一下目标部位有哪些动作、每个动作的姿势要点和常见错误。
  - 养成（v0.6）：把当天的三餐 / 喝水 / 运动打卡换成经验和金币，喂宠物、买家具、装点自己的小窝。

## 三、输入 / 处理 / 输出（IPO）

| 环节 | 内容 |
|---|---|
| **输入** | ① 身体数据：性别、年龄、身高、体重、活动量、人群 <br> ② 今日已吃：从食谱列表里点选 |
| **处理** | ① 三步公式算出每日目标卡路里 <br> ② 累加已记录食谱的五类营养 <br> ③ 按「剩余额度 + 人群标签」排序推荐 |
| **输出** | 目标卡路里、今日已摄入 / 剩余、五类营养合计、3 道推荐食谱 |

## 四、验收条件（A1 用的就是这个）

> 用户打开网页 → 填写身体数据并点击「计算目标」→ 页面显示一个每日目标卡路里 →
> 从「全部食谱」点几道菜「记录」→ 上方卡路里数字增加、进度条变长 →
> 当已摄入超过目标时，进度条变红 →
> 下方「为你推荐」列出 3 道属于当前人群、且今天还没吃过的菜。

以上每一步都能肉眼观察，不需要任何人解释。

## 五、核心规则（写死的，不做可选）

### 5.1 人群（固定 4 类）

减脂 / 增肌 / 控糖 / 均衡。不做自定义人群，不做问卷测试。

### 5.2 每日目标卡路里：三步计算

**第一步 · 基础代谢 BMR（Mifflin-St Jeor 公式）**

- 男：`BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 + 5`
- 女：`BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 − 161`

**第二步 · 乘活动系数得到每日消耗 TDEE**

| 活动量 | 系数 |
|---|---|
| 久坐（几乎不运动） | 1.2 |
| 轻度（每周1–3次） | 1.375 |
| 中度（每周3–5次） | 1.55 |
| 高度（每周6–7次） | 1.725 |

**第三步 · 按人群微调**

| 人群 | 系数 |
|---|---|
| 减脂 | × 0.8 |
| 增肌 | × 1.1 |
| 控糖 | × 1.0（不增减） |
| 均衡 | × 1.0（不增减） |

**固定边界**

1. 结果**取整到 10 kcal**：`round(值 / 10) × 10`。
2. 取整后若 `< 1200`，显示 **1200**，并提示「目标过低，已自动上调」。
3. 下限判断放在取整**之后**。

**标准示例（用作回归测试用例）**

> 22 岁女性，165 cm，55 kg，久坐，减脂：
> `BMR = 10×55 + 6.25×165 − 5×22 − 161 = 1310.25`
> `TDEE = 1310.25 × 1.2 = 1572.3`
> `减脂 = 1572.3 × 0.8 = 1257.84` → 取整到 10 → **1260 kcal**

### 5.3 食谱字段契约（所有食谱必须一模一样）

| 字段 | 类型 | 单位 | 规则 |
|---|---|---|---|
| id | 字符串 | — | 唯一，格式 `r` + 三位数字 |
| 名称 | 字符串 | — | 非空 |
| 人群 | 字符串数组 | — | 至少 1 个；只能取「减脂/增肌/控糖/均衡」 |
| 卡路里 | 整数 | kcal | 0 ≤ 值 ≤ 3000 |
| 碳水 | 数字 | g | ≥ 0，保留 1 位小数 |
| 脂肪 | 数字 | g | ≥ 0，保留 1 位小数 |
| 膳食纤维 | 数字 | g | ≥ 0，保留 1 位小数 |
| 蛋白质 | 数字 | g | ≥ 0，保留 1 位小数 |
| 食材 | 字符串 | — | 非空；食材清单（v0.2 新增） |
| 步骤 | 字符串数组 | — | 非空数组，每条一个做法步骤（v0.2 新增） |
| 图片 | 字符串 | — | 本地相对路径 `数据/图片/<id>.jpg`；空字符串表示暂无配图 |

固定规则：

1. 字段名固定，绝不混用（不写 `kcal`、`Calorie`、`carbs`）。
2. 数字只写数字，不带单位（写 `420`，不写 `"420 kcal"`）。
3. 卡路里为整数；其余四项固定保留 1 位小数（写 `9.0`，不写 `9`）。
4. 五类营养**必须齐全**，缺任一字段即视为无效数据。
5. 图片**必须本地化**，禁止外链，保证断网可用。

### 5.4 推荐规则

1. 只从**当前人群标签**里挑。
2. 今天**已经记录过的菜不再推荐**。
3. 每餐预算 ≈ 剩余额度 ÷ 3，选卡路里最接近预算的。
4. 同分时按人群偏好加分：减脂看蛋白/脂肪比，增肌看蛋白，控糖看低碳水 + 高纤维。
5. 剩余 ≤ 100 kcal 时不再推荐，显示「今日已达目标额度」。
6. 「换一批」（v0.4.1）：在同一排序候选中按偏移向后翻 3 道，到尾自动回绕；
   候选总数不足 3 道时按钮禁用；记录或目标变化后偏移归零。

### 5.5 一周食谱计划规则

1. **固定 7 天**，每天最多三餐（早 / 午 / 晚）。界面上不提供 30 天选项。
2. 逐日扣减额度：每餐预算 = 当日剩余额度 ÷ 剩余餐数。
3. 从「当前人群 + 本周未用过 + 当天未用过 + 单餐不超剩余额度」的候选里，
   选卡路里最接近餐预算的。
4. 本周可选项用尽时，允许跨天重复，但**同一天内仍不重复**。
5. 单餐卡路里**不得超过当日剩余额度**，避免出现「预算 40 却推 160」的情况。
6. 计划存入 localStorage，键名 `食谱搭配-一周计划`，可清除重生成。

### 5.6 食谱专区（按人群分区）

1. 分区：全部 / 减脂 / 增肌 / 控糖 / 均衡，显示各分区食谱数量。
2. 每条食谱以卡片展示：图片位、菜名、人群标签、五项营养、卡路里、份量选择、记录按钮。
3. **搜索**（v0.4.1）：按菜名包含匹配，与分区过滤叠加；无结果时给出提示。
4. **排序**（v0.4.1）：默认（按 id）/ 热量低→高 / 热量高→低，同卡路里按 id 稳定排序。
5. **分区记忆**（v0.4.1）：上次选择的分区存入 localStorage（键名 `食谱搭配-食谱分区`），刷新后保持。
6. **图片字段**：`菜.图片` 指向 `数据/图片/<id>.jpg` 本地文件，**断网也能显示**。
   为空字符串时显示占位块（图标 + 无障碍标签），加载失败自动退回占位块。
   不允许使用外链（测试会拦截 `http://` / `https://` 开头的图片路径）。
7. 当前 40 条食谱**全部有配图**。其中 r001–r024 的 24 张来自 Unsplash（遵循 Unsplash License）
   或课程作业专用素材；r025–r040 的 16 张为 AI 生成配图（2026-11-13，供本课程作品使用），
   菜品内容参考《减脂饮食全书》（github.com/da-damu/fat-loss-diet-book）。
   来源均注明于 README。
8. **默认限量显示**（v0.4.3 版式优化）：普通浏览只渲染前 **12 道**，并显示
   「显示 12 / 40 道」与「显示全部 40 道」按钮；点展开后记住状态
   （`食谱搭配-专区展开`），可再收起。**搜索或排序生效时自动给全量结果**——
   带着目的找菜时不能截断。分区按钮的数量计数始终是真实总数（如「全部 40」），
   不受限量显示影响。纯函数 `专区显示条数()` 由 `逻辑复算.py`【14】复算。

### 5.7 页面结构（v0.5 改为多页面 + 左侧常驻导航）

用户反馈「单页堆太多、要一直往下划」，v0.5 起把饮食 / 训练双分区改成 **6 个独立 HTML 页面**，
每页一个功能区，左侧导航栏常驻，点击即进入对应页面；相关功能合并到同一页。

| 页面 | 文件 | 内容 |
|---|---|---|
| 🥗 今日总览 | `index.html` | 今日摄入 + 为你推荐（首屏并排）+ 今日记录速览 |
| 🎯 我的目标 | `目标.html` | 身体数据表单 + 目标结果 + 三步公式说明 |
| 📖 食谱专区 | `食谱.html` | 40 道食谱、分区 / 搜索 / 排序 / 做法 / 记录 + 使用说明 |
| 🗓 一周计划 | `计划.html` | 7 天计划生成、标记已吃、偏差分析 + 计划规则 |
| 🕘 记录与回看 | `记录.html` | 今日已记录（可移除 / 清空）+ 近 7 天回看 |
| 💪 动作库 | `训练.html` | 30 个动作教程 + 安全说明 |

设计要点：

1. 六个页面共用 `样式.css`、`脚本.js` 与 `数据/`，用 `<body data-页面="…">` 标明身份；
   脚本按页面只绑定本页控件、只渲染本页区块；缺失元素由 `取元素()` 的哑元素兜底，不抛错。
2. 侧栏写死在每个 HTML 的 `<aside class="侧栏">`（不依赖 JS 也能导航），
   当前页高亮由 `高亮导航()` 依据 `data-页面` 设置；`检查契约.py` 校验 6 页导航与 id 一致。
3. 侧栏常驻显示每日目标与「今日 N 道 · X kcal」：在食谱页 / 推荐页点「记录」也能立即看到反馈。
4. 所有页面共享同一份 localStorage，换页、刷新都不丢数据；同浏览器多标签用 `storage` 事件同步。
   已用无头浏览器写入独特值后逐页读取，确认 `file://` 下六页共享存储。
5. 响应式：≤900px 侧栏收成顶部横向导航（允许换行，6 项全部可见），内容单列；
   ≤560px 隐藏重复的顶栏目标，但保留侧栏紧凑目标条与今日计数。
6. v0.4.x 的「吸顶主分区切换 / 左栏三标签 / 区块快速跳转」由侧栏取代，相关运行时代码已删除；
   纯函数 `初始左栏面板()` 仍保留供回归测试套件【15】覆盖（历史契约，不参与页面渲染）。
7. 营养与动作的数据字段契约、三步公式、推荐 / 计划规则、存储键名均未改变。

> 版式演进：v0.2 双分区 → v0.4 自然系视觉重构 → v0.4.3 首屏并排 / 计划前置 / 专区限量
> → v0.4.5 左栏标签化 → **v0.5 多页面拆分**。

### 5.8 健身动作教程（v0.2 新增）

   © Gym visual 专有授权，**未使用**。

**示意图机制**

找不到准确照片的动作**不放错图**，改用内置 SVG 简笔示意图（按部位区分姿态剪影）。
**v0.4.4 起 28 个动作全部有本地照片**；A4 交接实测新增的 e029 反向卷腹与 e030 保加利亚分腿蹲
暂无配图，走 SVG 示意图兜底——**当前共 30 个动作，其中 28 个有照片、2 个用示意图**。
配图构成：5 张课程专用素材（e001 / e002 / e004 / e009 / e013）+

v0.4.4 统一去除生图工具加在右下角的水印。全部为本地文件，断网可显示。

**安全边界（重要）**

1. 页面明确声明：内容为通用健身参考，**不构成专业教练指导或医疗建议**。
2. 有伤病、心血管疾病、孕期等特殊情况，提示先咨询医生或专业教练。
3. 不做动作识别、不做实时纠正——本版本不接摄像头。

### 5.9 数据存放

- 食谱数据：`数据/食谱.js`（由 `数据/foods.json` 转换，便于本地双击打开时免跨域读取）。
- 动作数据：`数据/动作.js`。
- 用户记录与目标：浏览器 `localStorage`，键名 `食谱搭配-今日记录` / `食谱搭配-今日目标`。
- 一周计划：`食谱搭配-一周计划`。
- 当前页面：由 `<body data-页面>` 决定，无需存储（v0.5 起删除 `食谱搭配-主分区` 键）。
- 食谱专区上次分区：`食谱搭配-食谱分区`（v0.4.1）。
- 近 7 天历史记录：`食谱搭配-历史记录`；今日记录日期戳：`食谱搭配-记录日期`（v0.4.1）。
- **不做**后端、不做账号、不做云同步、不调用任何在线接口。

## 六、三不原则（本项目当前绝不做的三件事）

> 本版本 v0.6 **明确不做**，不是"以后再说"，是当前范围外：

1. **不做**账号注册、云端同步、多用户。
2. **不做**花哨的可视化图表（环形图、趋势曲线、柱状图对比等）。
3. **不做**一个月（30 天）的食谱计划。

**为什么**：这三件事都会让项目在两周内变成做不完的焦油坑。先把「算目标 → 记一天 → 推荐下一餐」和「查动作 → 学要点」这两条主链路做扎实。

**逐条理由**：

| 条 | 拒绝场景 | 为什么拒绝 |
|---|---|---|
| 1 | 「能不能同步到手机 / 加个登录」 | 一旦有账号就有服务器、权限、隐私合规，作品从本地工具变成半个产品 |
| 2 | 「进度条太朴素了，加个环形图 / 趋势曲线吧」 | 一个进度条已把「还剩多少」说清楚；多一种图表就多一类空数据与极端值边界。属第 8 周《画蛇添足》典型陷阱 |
| 3 | 「能不能直接排一个月的食谱？」 | 一个月等于 90 餐，需要处理重复、口味疲劳、食材浪费；7 天已足够暴露问题，30 天只是把同样的逻辑拉长，收益低而返工多 |

**怎么用**：以后有人（包括 AI）建议加这三类功能，直接引用本节，在 Issue 里写明「超出当前三不原则」，推迟到后续版本。

## 六之二、范围变更记录

三不原则是**当前版本**的边界，不是永久的禁令。当某个被排除的功能确实值得做时，不走「偷偷加」，而是走「记录 → 论证 → 放开」的受控流程。

**变更流程**：

1. 在 GitLab 建 Issue，标题写明要放开第几条三不原则。
2. 在 Issue 中写清三项：**触发原因**、**对现有契约的影响**、**验收标准**。
3. 评审通过后，在下方表格新增一行，并在「当前三不原则」一节同步修订条目编号。
4. 变更提交的提交信息以 `范围变更：` 开头，便于 `git log --grep` 追溯。

## 八、已知限制

1. 营养数据为教学用估算值，**不构成医学或营养建议**。
2. 历史记录只保留最近 7 天的**纯文字回看**（v0.4.1），不做更长历史、不做图表。
3. 推荐只做简单排序，不考虑口味偏好、过敏原、烹饪时间。
4. 需要在现代浏览器中打开（Chrome / Edge），不支持 IE。
5. **全部功能完全离线**：40 条食谱写死在 `数据/食谱.js` 中，不调用任何在线接口；
   所有数据均可人工核对。（v0.3 曾设可选 AI 助手，v0.4 已移除，见六之二范围变更记录。）
6. **零依赖在 v0.6 仍成立**（两点补充说明）：
   ① 3D 房间与角色渲染使用浏览器原生 WebGL2（不可用时降级 WebGL1 / 2.5D），渲染器是手写的约 560 行代码，
   **没有引入 three.js 或任何第三方库**；模型以 base64 内嵌成 `.js` 文件加载（`file://` 下不能 fetch），
   仍可双击打开、断网可用。
   ② 着色器源码（GLSL）的标识符**必须全 ASCII**，这是「全中文命名」约定唯一的例外——
   中文标识符会报 `'?' : syntax error`，且看不出跟中文有关（v0.6 实测踩坑两次）。
7. 小窝页首次要读约 38MB 的 3D 模型（房间 15.4MB + 角色 23.2MB），软件渲染下首帧约 10 秒；
   之后走浏览器缓存。**玩法与模型解耦**：WebGL 不可用时只隐藏小窝，打卡 / 换装 / 宠物照常可玩。（v0.6）
8. 换装目前只能改颜色：角色是单一融合网格，衣服烘在贴图里；换款式需要单独的低模服装包。（v0.6）
9. 养成存档为**单存档**（本机 localStorage），不做多档位与云端同步；换设备靠导出 / 导入文本。（v0.6）

### 5.10 食材与做法（v0.2 新增，借鉴 CookHero 菜谱查询）

1. 每条食谱带「食材」（字符串）与「步骤」（字符串数组，3–5 条）。
2. 食谱专区的卡片有「做法」按钮，展开显示食材清单与编号步骤，默认收起。
3. 新增菜品（r025–r040）的做法参考《减脂饮食全书》整理；既有 24 道菜为人工补写。

### 5.11 餐次与「标记已吃」（v0.2 新增，借鉴 CookHero 计划 → 记录闭环）

1. 点「记录」时按当前时间自动归入餐次：< 10 点为早，< 15 点为午，< 21 点为晚，其余为加餐。
2. 「今日已记录」列表中每条显示所属餐次标签。
3. 一周计划的第 1 天视为今天：每餐有「标记已吃」按钮，点击后该餐转入今日记录（按计划餐次归档），
   按钮变为「已吃 ✓」徽章。标记状态存入一周计划存档的 `已吃` 数组。

### 5.12 宏量营养目标与偏差分析（v0.2 新增，借鉴 CookHero 目标管理 / 营养分析）

1. 目标卡路里按人群供能比换算出蛋白质 / 脂肪 / 碳水三项目标（克）：
   减脂 30/25/45，增肌 25/25/50，控糖 25/35/40，均衡 20/30/50（蛋白质/脂肪/碳水）。
2. 换算公式：目标克数 = round(目标卡路里 × 供能比 ÷ 每克供能)，每克供能：蛋白质 4、脂肪 9、碳水 4。
3. 「今日摄入」面板在设置目标后显示三项目标值（如「g / 目标 95」）。
4. 生成一周计划后，在计划区显示**一句话文字偏差分析**：今天（第 1 天）计划合计 vs 实际记录，
   多/少约多少 kcal。**只做文字，不做图表**（见三不原则第 2 条）。

### 5.13 份量与近 7 天回看（v0.4.1 新增）

**份量（整份 / 半份）**

1. 推荐行与食谱卡的「记录」旁有份量选择（整份 1 / 半份 0.5），默认整份。
2. 折算规则：卡路里 = round(原值 × 份量)；四项克数保留 1 位小数（复刻 JS 的 Math.round）。
3. 记录条目带唯一键 `记录id`：同一道菜记两次（如整份 + 半份）可分别移除；
   旧存档无 `记录id` 时回退按菜品 id 移除。
4. 半份记录在「今日已记录」与历史回看中显示「（半份）」标注。

**近 7 天记录回看（纯文字，不做图表）**

1. 存储键 `食谱搭配-历史记录`，值为 { 日期: [记录条目] }；`食谱搭配-记录日期` 存今日记录的日期戳。
2. 页面加载时结转：上次记录日期 ≠ 今天 → 当时记录存入历史并清空今日记录；同一天不动；
   旧版本存档无日期戳时视为今天，只补日期不结转。
3. 历史只保留最近 7 天，超出删除最老的。
4. 左栏「近 7 天」面板按日期倒序展示：日期 + 条数 + 合计 kcal，
   点标题行展开当日明细（餐次 / 菜名 / kcal）。
5. 该功能为**纯文字回看**，不做图表（守三不原则第 2 条）、不做云端（守第 1 条）。

### 5.14 空状态引导（v0.4.1 新增）

### 5.15 养成系统「我的小窝」（v0.6.0 新增，详见 `养成系统-方案-v3.md`）

**定位**：把已有的打卡行为（记录一餐 / 喝水 / 运动）换成**经验 + 金币**的正反馈，
用金币养宠物、买家具、装点 3D 小窝。是第 7 页独立页面，**不改变任何饮食规则与数值**。

**分层（硬性约束）**

| 层 | 文件 | 职责 | 禁止 |
|---|---|---|---|
| 规则层 | `养成.js` | 29 个纯函数：等级 / 连签 / 结算 / 场景 / 宠物 | **不碰** DOM、localStorage、系统时间（今天与小时由参数注入） |
| 存储与视图层 | `养成反馈.js` | 4 个存储键、换天归一、侧栏经验块、手机胶囊、任务区、浮动提示 | 不自己实现规则，一律调规则层 |
| 渲染层 | `养成.html` | 3D 客厅 + 手机桌面 + 像素宠物 | 由 `工具/生成养成页.py` 装配，**是产物，不手改** |

**核心规则**

1. **只看「有没有打卡」，完全无视卡路里**。卡路里一旦参与奖励，用户会为了升级少吃，
   与 5.2 的 1200 kcal 下限保护自相矛盾。
2. 奖励表：早餐 20 经验 / 5 金币，午餐 20 / 5，晚餐 20 / 5，喝水 5 / 1，运动 30 / 8，一日达标 +50 / 20。
3. 每日目标 = 三餐 3、喝水 6、运动 1；每日上限 = 喝水 8、运动 3。
   **达标线低于上限**——达标要留余量，喝到第 9 杯才灰化。
4. 等级 1–10，升级所需 `100 + (等级−1)×100`，满级累计 4500 经验；满级后每 500 经验 +1 星（`Lv.10 ★3`）。
5. **断签只归零连签，不扣经验 / 等级 / 物品**；连签只给限定装饰，不给货币（不防作弊，改系统时间无收益）。
6. 家具加成只作用于**金币**（`Math.round(金币 × (1 + 加成))`），**经验永不加成**；6 件合计 +0.35，上限 0.5。
7. **唯一挂载点**：`脚本.js` 的 `添加记录()` → `try{ 养成反馈.餐后结算(餐次, !!指定餐次) }catch{}`。
   养成出任何错都不影响记录主链路。

**两个必须改掉的坑（R1 / R2，见方案 v3 第 2 章）**

| 坑 | 现象 | 规则 |
|---|---|---|
| R1 加餐兜底 | 21 点后记晚餐会被归成「加餐」，晚睡的人永远拿不到「晚」的经验、当天不可能达标 | 「加餐」来源若当天还没有「晚」，**兜底记为「晚」**（仅一次） |
| R2 计划页刷经验 | 计划页「标记已吃」带强制餐次，早上 8 点就能把晚餐标成已吃，5 分钟刷满一天 | 强制餐次校验**时间窗**：早 4–10 点、午 10–15 点、晚 15 点–次日 4 点；窗外记录照写但**不给经验** |

**渲染与降级（人物 2D + 房间 3D 混合）**

1. 房间：手写 WebGL 渲染器（盒 / 柱 / 球三图元 + 法线矩阵 + 半球光 + 接触阴影），地板与墙纸可换色。
2. 家具：8 件独立 GLB（`数据/模型/*.js`，一件一个模型），摆位唯一数据源是 `生成养成页.py` 的 `陈设` 表，
   `高` 以玩偶身高 1.0 为单位换算。
3. 角色：保留 30 骨骼的蒙皮玩偶（23.2MB），片元着色器按「高度带 + 底色」染色实现上衣 / 裤子 / 鞋换色。
4. 交互：单指拖转视角（偏航夹在正面扇形内，看不到背面）、双指 / 滚轮缩放、轻点玩偶挥手；
   WebGL2 缺失时只隐藏小窝，玩法不受影响。

**预设捏脸（不做上传、不做滑块）**

脸型 / 肤色 / 眉 / 眼 / 嘴 / 腮红 / 发型 / 上衣 / 裤子 / 鞋 / 配饰共 11 类，
`数据/装扮.js` 提供 38 件部件（其中肤色 4 档**全部免费**），只从网页给的选项里挑。

**存档**

单存档，存在本机 localStorage；提供**导出 / 导入**（textarea + JSON 校验）作为防丢失与换设备手段。
导入非法内容要有提示且不破坏现有存档。这不属于云端同步（守三不原则第 1 条）。
