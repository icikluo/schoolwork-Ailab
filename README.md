## 一、本学期自选作品

### 🥗 食谱搭配（网页版）

一个按人群推荐、可记录每日饮食的食谱工具。**纯前端、零依赖，双击就能跑，全部功能断网可用。**

**运行方式**

```bash
# 方式一：直接双击
自选作品/index.html

# 方式二：在文件管理器里打开
D:\lab\自选作品\index.html
```

不需要安装 Node.js、不需要 npm install，也不需要联网。

**页面结构（v0.6）**：7 个 HTML 共用左侧常驻导航，一页一功能区 ——
今日总览 / 我的目标 / 食谱专区 / 一周计划 / 记录与回看 / 动作库 / 我的小窝。
双击 `index.html` 进入总览，侧栏点击即可切换，当前页高亮。

**v0.6 新增「我的小窝」**（`养成.html`）：真 3D 客厅装在竖屏手机壳里（单指拖转视角、
双指 / 滚轮缩放、轻点玩偶挥手），右侧是手机桌面，6 个 app 分别打开任务板、换装、
像素宠物、存档柜，以及食谱专区 / 动作库入口。打卡自动计经验与金币
（早/午/晚各 20 经验、喝水 5、运动 30、一日达标 +50），金币可买家具与宠物的零食 / 玩具。
规则层 `养成.js` 是 29 个纯函数，不碰 DOM 与系统时间，用 Python 对拍验证。

**主要功能**

| 功能 | 说明 |
|---|---|
| 每日目标卡路里 | 三步公式（基础代谢 → 活动系数 → 人群调整），结果取整到 10，低于 1200 自动上调 |
| 宏量营养目标 | 按人群供能比换算蛋白质 / 脂肪 / 碳水三项目标 |
| 今日记录 | 点「记录」加入当天，自动归入 早/午/晚/加餐 餐次，实时累加五类营养 |
| 自动推荐 | 按人群 + 剩余额度推荐 3 道今天还没吃过的菜，可「换一批」 |
| 份量支持 | 记录时可选整份 / 半份，营养按比例折算 |
| 食谱专区 | 按 减脂 / 增肌 / 控糖 / 均衡 分区浏览 40 道菜，每条带配图，支持菜名搜索与热量排序，点「做法」看食材与步骤 |
| 近 7 天记录 | 换天自动结转，纯文字回看最近 7 天（不做图表） |
| 一周计划 | 生成连续 7 天的三餐安排，今天的一餐可一键「标记已吃」转入记录，附偏差分析 |
| 动作库（独立页面） | 30 个健身动作教程，按上肢 / 下肢 / 核心 / 全身分区，每卡带器械标签 |
| 我的小窝（独立页面） | 3D 客厅 + 手机桌面：任务板（三餐 / 喝水 / 运动 + 达标徽章）、换装、像素宠物（3 只、6 种表情、金币商店）、存档导出 / 导入 |

python 测试/检查契约.py     # 7 页（含养成页）的 id / 导航项 / data-页面 与 JS 的 取元素() 一致性
python 测试/核对养成.py     # 105 项：养成规则层（等级 / 连签 / 结算 / 家具场景 / 宠物）
python 测试/核对商店.py     # 22 项：商店数据与结算购买的契约

九个脚本全绿，表示数据、公式、页面契约、养成规则与数据契约都正常。

> Windows 下若 `逻辑复算.py` 报 `UnicodeEncodeError`（终端默认 GBK，编不出 `✓`），
> 先执行 `set PYTHONUTF8=1`（PowerShell：`$env:PYTHONUTF8='1'`）再跑即可。

## 五、三不原则（当前版本 v0.6 绝不做的三件事）

1. **不做**账号注册、云端同步、多用户。
2. **不做**花哨的可视化图表（环形图、趋势曲线等）。
3. **不做**一个月（30 天）的食谱计划。

详见 [`自选作品/文档/PRD.md`](./自选作品/文档/PRD.md) 第六节。

> 三不原则是当前版本的边界，不是永久禁令。
> 需要放开时走 `PRD.md` 第六之二节规定的范围变更流程（Issue → 影响面分析 → 验收标准 → 记录）。

## 六、已知限制

- 营养数据为教学用估算值，**不构成医学或营养建议**。
- 历史记录只保留最近 7 天的纯文字回看。
- 一周计划固定 7 天，不提供 30 天。
- 小窝页要读约 38MB 的 3D 模型（房间 15.4MB + 角色 23.2MB），首次打开有明显等待（软件渲染约 10 秒），之后走浏览器缓存。
- 小窝的换装只能改颜色：角色是单一融合网格，衣服烘在贴图里，换款式需要单独的低模服装包。
- 全部功能离线可用（v0.3 曾设可选 AI 助手，v0.4 已移除）。
- 需在被现代浏览器打开（Chrome / Edge），不支持 IE。

## 七、开发说明

本项目的开发过程遵循课程要求的「5 阶段人机协同证据链」：

```
意图声明 → AI 方案 → 人类审查 → Git 差异与测试 → 决策归档
```

具体体现：

- 每一条提交只做一件事，提交信息写清「问题 / 原因 / 修复 / 验证」
- 所有功能改动都伴随测试更新
- 个人手工改动与参数实验留有完整记录（见 `作业/A1/`）
